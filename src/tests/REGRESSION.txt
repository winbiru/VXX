V++ native regression tests
==========================

Source fixtures and expected outputs remain in src/tests. regression.json
registers the tests and accounts for all other .vi files, including imported
modules and special-purpose fixtures. The runner rejects new visible source
files or golden snapshots that are not recorded in the manifest.
Current inventory: 357 active full-native cases, 14 active i32 cases,
4 pending cases and 111 other source files accounted for by role. Some
cases use multiple sources or run an entire historical harness.

Run from the repository after building the V++ compiler:

  ./run_tests.sh --inventory
  ./run_tests.sh --list
  ./run_tests.sh --suite smoke
  ./run_tests.sh --case native_return_semantics
  ./run_tests.sh --shard-count 16 --shard-index 0
  ./run_tests.sh build-pure-vpp/bin/vpp-i32 --suite i32

  ctest --test-dir build-pure-vpp -L smoke --output-on-failure
  ctest --test-dir build-pure-vpp -L regression --output-on-failure
  ctest --test-dir build-pure-vpp -L i32 --output-on-failure

The default run_tests.sh suite is the complete registered full-native suite,
not the five-test smoke suite. The full suite compiles each .vi independently,
runs it in an isolated temporary working directory, compares stdout against
the pre-existing golden (only CRLF is normalized) and checks exit status.
Negative tests require the expected build rejection or exact runtime error
code, exit status and empty stdout. Legacy text diagnostics are preserved in
historical_expected; the pure AOT runtime currently reports numeric codes.
The structured file-error fixture checks the original full output. The DNS mock checks 23 modes and the HTTP server must become ready
on localhost; a denied bind is a failure, not a passing skip. Every failed
build/run has separate stdout, stderr and status logs. Results are stored in
a fresh run directory under --logs (default build-pure-vpp/regression-logs).
--timeout specifies a per-process timeout in seconds (default 900).
Standalone VM phases have a longer harness timeout and preserve nested
diagnostics under vm-diagnostics. The manifest also registers deterministic
compiler dumps, native linker oracles, and standalone VM core, system,
directory, process, resolver, negative socket and TLS tests. The i32 bit
driver compares 3249 results against the historical arithmetic oracle.

CI uses packaged compilers in separate jobs: 16 full-native shards each on
macOS ARM64 and Linux x86-64, and i32 regression on macOS, Linux and Windows.
Shards are balanced using historical timing estimates; HTTP cases share
shard 0 to avoid port conflicts. Mach-O codegen and linker oracles are
Darwin-only; ELF partial-linker oracles are Linux-only. Windows has
only the i32 compiler at present; full dynamic tests require that port.
The full regression matrix runs after compiler artifact publication, so
individual failures cannot prevent other shards from running. Failures
are retained in the workflow artifacts. The initial macOS package probe
and source/extension/inventory checks remain the fast build gate.

Pending and platform-unsupported cases are reported separately from passes.
Pending cases include retired JIT execution modes and two historical i32 syntax forms (assignment inside
short-circuit expressions and parenthesized INT32_MIN). The supported i32
callable short-circuit fixture still checks observable side effects. Raw
C host ABI cross-link parity harnesses require a separate V++/ASM port.
The unregistered_sources inventory identifies supporting
modules and remaining specialized tests which still need independent oracles
or ported harnesses. Do not generate expected output from the compiler being
tested or remove tests from the manifest to make CI green.

When adding a test, add a .vi file, an independent golden or other
historical/explicit oracle, and register it in regression.json. If a .vi file
is a helper, record its role in unregistered_sources instead.
