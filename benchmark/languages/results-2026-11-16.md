# Kết quả benchmark V++ ngày 16/11/2026

Lần đo chạy trên **macOS 26.6.2 ARM64** tại commit `c6b6f5d` với cây làm
việc có thay đổi. Compiler và runtime V++/ASM được dựng ở commit `9929796`.
Các commit kế tiếp chỉ cập nhật seed, tài liệu và kiểm tra bootstrap.
Compiler này biên dịch lại các ứng dụng benchmark, sinh Mach-O và liên kết
`libSystem`.

**21/21 workload ứng dụng**, 82 tổ hợp runtime/workload, **246/246 mẫu hợp lệ**.
V++ AOT, JavaScript và Python chạy đủ 21 bài. C (3 bài), C++ (5), Java (5)
và Ruby (6) chạy toàn bộ bài hiện có trong bộ đối chứng của chúng.
C/C++ dùng Apple Clang 21 `-O3` (LTO tắt). Node.js 20.11.1 và Java 21.0.2
dùng JIT mặc định. Python 3.14.3 và Ruby 2.6.10 dùng cấu hình mặc định.
Mã C++ và driver C/i32 lấy từ commit `35aa30e` và dựng lại cho lần đo này.

## Kernel i32 (ABI chung với C)

Đo riêng 3 kernel bằng object do compiler V++ native xuất trực tiếp
(`--emit-obj-selfhost`), dùng cùng driver C++ và ABI bốn tham số i32
với C, không LTO. Có 18/18 mẫu hợp lệ từ 6 tổ hợp. **Đơn vị là ns/lượt.**

| Kernel | V++ i32 | C |

| Fibonacci vòng lặp | 21.864 | 9.437 |

Bảng ứng dụng dùng bộ đo viết bằng V++, còn bảng kernel dùng driver C++.
Hai bộ đo có chi phí riêng nên hiệu giữa hai bảng cũng bao gồm khác biệt
do bộ đo.

## Phương pháp và phạm vi

Mỗi tổ hợp chạy 3 tiến trình độc lập, mỗi tiến trình có 3 batch làm nóng
và một batch đo, thứ tự xáo trộn, hiệu chỉnh mục tiêu 30 ms/batch. Batch
ứng dụng thực tế dài 21,14–181,11 ms (bài chậm có tối thiểu 16 lượt).
MAD/trung vị cao nhất 3,95% ở bảng ứng dụng và 2,95% ở bảng kernel.
Đầu vào luân phiên 16 seed `17..32`. Oracle Python độc lập kiểm tra
16 kết quả và checksum từng mẫu. Batch đo gồm vòng lặp bộ đo, gọi hàm,
cấp phát và GC còn lại sau tối ưu. Biên dịch, khởi động, chuẩn bị fixture
và làm nóng diễn ra trước đó. Các runtime sử dụng thư viện và cấu trúc
dữ liệu bản địa tương ứng, nên các bài JSON cũng phản ánh hiệu quả thư viện.
Phạm vi của lần đo này là thời gian thực thi ứng dụng AOT và kernel i32
trên máy và cấu hình đã nêu.
